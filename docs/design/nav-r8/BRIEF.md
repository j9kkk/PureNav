# PureNav nav-r8 —— 单页统一工作台（前后台合并）

> 状态：**设计定稿讨论中，未开始实现**。本文件只固化已拍板的结构决策，供视觉稿与后续实现对齐。

## 1. 核心变更

原架构是两套路由：`/`（前台工作台，只读）+ `/admin`（后台管理，登录态）。合并为 **单页**：

- 只有一个路由 `/`，前台即后台，登录后原地编辑，所见即所得。
- 顺序、分组、整体样式颜色全部在同一页面内调整，不再前后台跳转。
- `/admin`、`/settings`、`/account` 路由删除；`/login` 保留为独立路由（承载首次 setup），登录成功回跳 `/`。
- 后端 API 契约不变（`/admin/*` 保留），只是调用方从后台页面迁入前台抽屉与内联编辑器。

## 2. 三种页面状态

| 状态 | 判定 | 编辑控件 | 顶栏右端 |
| --- | --- | --- | --- |
| 访客 | 无 session | 全部隐藏 | 排序 · 视图切换 · **显眼的「登录」主按钮** |
| 登录 · 浏览 | 有 session，编辑开关关闭 | 全部隐藏 | `+ 收录` `数据` `外观` 用户菜单 · **「编辑」开关（关）** |
| 登录 · 编辑 | 有 session，编辑开关打开 | 拖拽把手、`···`、树节点 `＋`/`⋯`、标签 `＋`、拖拽插入线 | 同上 · **「编辑」开关（开）** |

设计意图：登录后默认仍是「浏览」，只有显式打开「编辑」才出现所有编辑控件。避免访客／登录两套布局，也避免长期挂着一堆可误触的把手。

## 3. 编辑落点（原后台功能去向）

| 原后台位置 | 新落点 | 触发 |
| --- | --- | --- |
| 书签批量管理（表格 + 多选批量） | 内容区卡片：拖拽排序、`⋯` 单条操作、登录态多选工具条 | 编辑态 |
| 分组 CRUD / 树拖拽排序 | 左侧目录树节点：`＋` 新建子目录、`⋯` 改名/移动/删除、拖拽排序与嵌套 | 编辑态 |
| 站点与数据设置（标题/logo/主题/布局） | 右侧 **外观抽屉**（360px） | 顶栏「外观」 |
| 导入 HTML / 导出 JSON / 书签 HTML / 快照 / 回收站 | 右侧 **数据抽屉** | 顶栏「数据」 |
| 账户：改密码、会话、审计日志 | **用户菜单**弹层 | 顶栏用户菜单 |
| 快速收录 | `+ 收录` 弹窗（现有 `.nx-dialog`） | 顶栏「收录」 |
| 书签体检中心 | 保持现状（侧栏智能视图「体检中心」） | — |

## 4. 已拍板的五个决策

1. **编辑开关**：顶栏提供显式「编辑」开关（44×24 胶囊），不开则纯浏览。
2. **登录入口**：访客态顶栏保留**显眼的主按钮**（强调色实底），不做隐藏。
3. **明暗主题全部由站点统一**：删除访客本地的明暗偏好与所有主题切换按钮（原侧栏底部月亮按钮、`readThemeOverride` / `writeThemeOverride` 的 localStorage override 机制一并废弃）；主题作为站点资产由 `site.theme` 统一下发，调整入口只在外观抽屉的「站点主题」。
4. **站点主题只留「浅色 / 深色」两档**，不做「跟随系统」。理由：站点统一主题的前提下，「跟随系统」意味着访客的系统明暗仍会改变观感，与「统一」冲突。
5. **编辑态不做多选**：只保留单条 `⋯` 操作 + 拖拽排序/移动；批量启停、批量移动、批量删除留在「数据」抽屉里，不进入编辑态。理由：多选需要额外的选择模式（复选框 / 框选），会让编辑态复杂度上一个台阶，而批量本身是低频操作。

> 第 3 条的连带影响：`apps/web/src/lib/theme.ts` 里的本地 override 分支与侧栏主题切换按钮需要移除，`applyTheme` 改为只读服务端配置。

## 5. 公网前提下的约束

站点公网可达，因此：

- 登录不可去掉；`/admin/*` 写接口保持 `requireAdmin` + 同源校验。
- 所见即所得意味着误操作不可逆 → 必须有：破坏性操作二次确认、删除后撤销 toast、软删除 + 回收站、写前快照。
- 待补安全项：`PURE_SECURE_COOKIE` 部署强制为 1；`POST /public/items/:id/hit` 匿名写库需限流。

## 7. 实现落地（首轮，代码已合入 main）

三态由根节点属性驱动，同一套 DOM：

| 状态 | 根节点属性 | 顶栏右侧 | 可用的编辑入口 |
| --- | --- | --- | --- |
| 访客只读 | `data-auth="anon" data-edit="false"` | 强调色实底「登录」按钮 | 无（无 `⋯`、无拖拽、无 `＋`、双击标题不进入改名、右键不出菜单） |
| 登录浏览 | `data-auth="admin" data-edit="false"` | 「编辑」开关（关闭态）+ 侧栏底部 4 个入口 | 同上，无 |
| 登录编辑 | `data-auth="admin" data-edit="true"` | 「编辑」开关（实底开启） | 快速收录 / 卡片拖拽 / `⋯` 菜单 / 右键菜单 / 文件夹 `＋` / 双击标题改名 |

已落到单页的能力：

- **外观抽屉**：站点主题（浅色/深色）、强调色 6 色、圆角滑杆、阴影三档、卡片密度、卡片尺寸、显示描述。全部写 `PATCH /admin/settings`，并即时以 `data-density` / `data-size` / `data-desc` 属性回落到工作台样式。
- **结构抽屉**：文件夹树平铺 + 缩进，行内改名（Enter 提交 / Esc 取消 / 失焦提交）、删除（二次确认，级联）、跳转到该文件夹、新建根文件夹。
- **数据抽屉**：导出 JSON / 浏览器书签 HTML、合并导入 / 覆盖导入（覆盖需确认）、体检重扫、跳转体检中心与收件箱。
- **卡片内联改名**：编辑态双击标题进入输入框，Enter / 失焦提交，Esc 取消。

## 8. 旧后台已删除（第二轮）

`/admin`、`/settings`、`/account` 三条路由与 `AdminPage` / `SettingsPage` / `AccountPage` / `GroupTree` / `SortableList` / `Switch` / `TagInput` 组件全部删除；旧地址命中时 `history.replaceState` 落回 `/`，不留死链。web 包从 366 KB 降到 313 KB。

删除前已把仍需要的能力搬进单页：

| 原后台能力 | 现在的位置 |
| --- | --- |
| 站点标题 / 描述 | 外观抽屉顶部两个输入框（失焦或 Enter 提交） |
| 主题 / 强调色 / 圆角 / 阴影 / 密度 / 卡片尺寸 / 描述显示 | 外观抽屉 |
| 分组改名 / 删除 / 新建 | 结构抽屉 + 侧栏文件夹区 |
| JSON 导出导出、浏览器书签 HTML 导入（多级目录） | 数据抽屉（导入分「合并 / 覆盖」两档，覆盖需二次确认） |
| 体检重扫 / 收件箱入口 | 数据抽屉 + 侧栏智能视图 |
| 退出登录 | 侧栏底部第四个图标按钮 |

已随之消失且不再提供 UI 的能力：站点 logo / favicon 上传、图标检索与上传、改密、登录会话管理、操作日志、内网地址/图标抓取安全开关。这些属于低频运维，服务端接口仍在，需要时可恢复为独立维护页。

## 9. 拖拽与焦点环（第二轮）

- 拖拽：编辑态下卡片可拖，落在目标卡片前半区/后半区改顺序（双列按左右半区、单列按上下半区判断），落在侧栏节点或子文件夹药丸即归档。顺序按「文件夹树前序 → 组内 `sortOrder`」落库，所以「全部书签」里各文件夹的条目不会互相穿插。
- 进入编辑态自动切到「按手动排序」，退出不改回，避免拖完看不到效果。
- 焦点：全站只保留 1px 强调色描边，删掉 `border-color + box-shadow` 叠出的双层环；搜索框、抽屉输入框、`.nx-input` 共用同一条规则。
