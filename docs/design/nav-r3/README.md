## 推荐：A 定轴三栏

理由，按权重排：

1. **问题闭环最完整**。审查里三条 P0（中段真空、玻璃叠玻璃、时钟侵占品牌区）在 A 里全部归零，
   且是靠布局约束而不是靠"看起来更紧"：搜索左右各 16px、中心 50.0% 是算法结果，窗口变宽变窄都不回退。
2. **信息零丢失、交互零变更**。时钟、三个入口、标签条全在原位，改造量 = 一段 CSS + JSX 顺序调整，
   不新增状态机。对 1733 张卡片的实际页面来说，回归面最小。
3. **B 的高度是有代价的**。105px 对"一天扫几百个站点"的首屏是净损失（对比 52px 少半行卡片），
   换来的只是"少一层浮岛"；而标签条在 A 里加了计数后已经不再读作散落的药丸。
4. **C 的正确部分可以后置叠加**。C 把低频入口收进「⋯」符合你的入口冗余偏好，
   但它的代价是每次进后台多一次点击，且搜索占到 68.6% 后整条栏变成 Raycast。
   A 的动作区是固定 256px，后续把主题/视图两项收进一个「⋯」就是了 C 的一半，不必现在一次做完。

## 选 A 之后的落地注意（不是设计问题，是工程坑）

- 时钟改名后，现有 `@media (max-width: 900px) { .brand-clock { display: none } }` 必须跟着改选择器，
  否则窄屏下面板里会多出一截文字。
- 标签条滑动指示块的宽度来自测量（`tagBarRef`），改过内边距或字号后必须让 `updateIndicator` 重跑，
  否则首帧指示块会错位。
- A 的品牌区固定 256px：站点标题是用户自建内容（`config.site.identity.title`），
  中文长名必须走 ellipsis，且要在 1200/1024 两档实测不被压。
- 三个图标按钮撤掉 `border/background/backdrop-filter` 后，hover 态只剩 `--lg-inset` 填充，
  深色下要确认 `--lg-inset`（rgba(255,255,255,.06)）在玻璃上仍可辨识。
