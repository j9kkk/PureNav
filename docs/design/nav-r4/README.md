# PureNav r4 —— 收起式搜索 + 透镜玻璃语言（参考 GooseHyperGlass 口径）

> **落地状态**：本节原型 = 已落地到 `apps/web` 的视觉来源。
> 落地时按用户决定**放弃收起式搜索**（搜索保持常驻展开），只取透镜材质与暗场曝光层；
> 收起态的状态机（g1/g2 里那套 focus/Esc/筛选提示）作为后续选项保留在原型里。
> 入库只保留关键帧，其余状态帧（dark/640/focus/menu 等）留在本地未提交。
> 真实应用截图见 `docs/screenshots/r4-*.png`。

产物目录：`docs/design/nav-r4/`
基线：r3 的 A「定轴三栏」（`docs/design/nav-r3/a-axis.html`）
参考图：`reference-glass-doc-hero.png`（glass.goose.cc.cd 文档站）
两版原型：`g1-lens-light.html`（浅色透镜）/ `g2-glass-dark.html`（暗场玻璃）

## 结论先行

1. **搜索收起方向：可做，已做，断言全过。** 但它是节奏取舍，不修任何已测缺陷。
2. **参考项目不能当重构基座**，只能当"语言词典"。理由见下面的实测表。
3. **推荐合并方案：浅色用 G1 的透镜，深色用 G2 的暗场，共用一套材质令牌、只切换"曝光层"。**
   G1 自己的深色模式是失败的（近黑死底，玻璃没东西可折），G2 的暗场才是暗色该有的样子。

## 一、搜索收起 / 展开：实测断言

四类断言，主线程用 CDP 在 1440×900 实测（`/` 与点击、Esc、焦点、几何位移）：

| 断言 | G1 实测 | G2 实测 | 判定 |
|---|---|---|---|
| 收起态栏高 / 展开态栏高 | 52 / 52 | 52 / 52 | 通过（无高度抖动） |
| 三个图标 x（收起 vs 展开） | 1048 / 1092 / 1136，两态相等 | 1048 / 1092 / 1136，两态相等 | 通过（iconXShift = 0px） |
| 点击展开后 `activeElement` | `INPUT#searchInput` | `INPUT#search-input` | 通过（同帧聚焦） |
| 按 `/` 唤起 | 展开 + 聚焦，宽 520 | 展开 + 聚焦，宽 480 | 通过 |
| Esc 收起后 `activeElement` | `BUTTON#searchTrigger` | `BUTTON#search-trigger` | 通过（焦点回归） |
| 收起态触发器 | 220×36，文本「搜索站点 /」 | 220×36，文本「搜索站点… /」 | 通过（不是光秃秃一个图标） |
| 展开态右缘到首个图标 | 928 → 1048，留 120px | 888 → 1048，留 160px | 通过（不压字） |
| 长查询截断（中文 30 字） | 文字叶子 `scrollWidth 410 > clientWidth 179`，ellipsis 生效，清除按钮仍在（x 678） | `411 > 151`，ellipsis 生效，清除按钮在 pod 内 x 600 | 通过（不溢出胶囊） |
| 640 / 375 横向溢出 | 0 / 0 | 0 / 0 | 通过 |

设计上必须守住的三条（也写进了落地要求）：

- **展开必须覆盖式**，不能把图标推走。栏高与图标 x 是硬验收线。
- **收起态不能只是一个图标**，要带文字与 `/` 键帽，否则每次搜索多一步"找入口"。
- **有活动查询时收起，必须显式提示**（`筛选中：xxx ×`）。否则列表被过滤而界面看不出原因，是这类设计最常见的翻车点。

## 二、参考项目实测（不采信文档宣传）

| 项 | 实测结果 | 含义 |
|---|---|---|
| 引入方式 | `https://glass.goose.cc.cd/liquid-glass.js`，345KB（gzip 95KB） | 自托管/内网/离线场景必须 vendor 到本地 |
| 组件本质 | 每个 `<liquid-glass>` 在 canvas 里**自带场景**（自画壁纸/黑底/蓝紫渐变） | 不是能叠在既有 DOM 上的材质。浅色页上 single-bottom-tabs 给的是紫蓝渐变底；buttons 模式整块纯黑 |
| 文本 | `shadowRoot` 里只有 `<canvas>`，`innerText` 为空 | 无 DOM 文本、不可选中、屏幕阅读器读不到、Tab 聚焦不到 |
| 光栅倍率 | 1192 CSS ↔ canvas 1192，**写 `dpr="2"` 仍是 1x** | Retina 上细线与中文会发虚 |
| 首帧 | 两个画布 `firstRaf` 350ms（shader 同步编译） | 顶栏一块可以接受，组件一多就卡首帧 |
| 帧率 | M1 Pro，两块小画布 62fps | 玻璃 chrome 本身不贵，贵在实例数量 |
| Context 上限 | 文档自述 6–8 个 | 1733 张卡片绝无可能 WebGL 化 |

**结论**：它是一套"组件 demo 运行时"，不是"能套在现有界面上的材质系统"。所以 r4 的做法是**借语言、不借运行时**——
双缘高光（内亮外暗表达厚度）、边缘极轻色差、体积折射环、液滴式形变，全部用 CSS 复刻。

## 三、G1 vs G2

| 维度 | G1 透镜玻璃·浅色 | G2 玻璃·暗场 |
|---|---|---|
| 地面 | `#f5f5f7` 纸感 + 蓝紫薄暮 | `#0A0D14` 暗场 + 多层博克光斑 |
| 玻璃厚度表达 | 双缘 inset（白 0.95 / 0.35）+ 外缘暗线 | 双缘 inset（白 0.22 / 0.05）+ 深投影 |
| 色差 | 蓝 0.16 / 紫 0.10 inset | 无（暗场靠高光，不靠色散） |
| 正文对比度 | 对照 DESIGN.md 原有灰阶 | 主墨 16.65:1、次墨 7.58:1、弱墨 5.39:1（实测） |
| 图标墨色对比 | `#56565C` 对实际玻璃像素 (237,234,255) = **6.64:1** | `#94A3B8` 对实际玻璃像素 (18,24,43) = **6.91:1** |
| 与 DESIGN.md「无彩账簿」 | 完全兼容 | 需要论证（见下） |
| 自身深色模式 | **偏弱**：近黑死底，玻璃无物可折，卡片层次粘连 | 即其本体 |
| 落地成本 | 低：既有浅色令牌 + 一层材质 | 中：地面、环境光、卡片面、三级墨全要重定 |

### 为什么推荐"浅 G1 + 暗 G2"合并，而不是二选一

两版共用同一套几何（都是 A 的定轴三栏、52px 栏高、36px 控件、16/16 空档）与同一套搜索状态机，
差别只在**曝光**：地面亮度、环境光强度、玻璃填充 alpha、色差有无。所以正确做法是抽出一层
`material` 令牌（厚度、双缘、体积环、液滴曲线，两版相同），加一层 `exposure` 令牌（按主题切换）。

- 白天/强光：浅色纸感，扫站点最省力（G2 的 notes 也承认暗场高频扫视更累）。
- 夜间：暗场透镜，玻璃才真正有东西可折——G1 自己的深色模式做不到这一点。

## 四、需要拍板的三件事

1. **色差要不要留。** G1 的蓝紫 inset（0.16 / 0.10）严格说踩了 DESIGN.md「不要引入第二个蓝、不做装饰色」。
   我的判断：**留，但要定性为光学现象而不是装饰**——它只在圆角边缘出现，且色相取自页面环境光（本来就是蓝紫）。
   若要绝对守规矩，去掉这两行、只留双缘高光即可，会少一点"玻璃"但更干净。
2. **暗色是否做默认。** 建议不做默认：保持浅色默认、暗色可选。理由是扫站点是高频动作，暗场白字在强环境光下更累。
3. **收起态读作输入框的歧义。** 两版收起态都长得像"可以直接打字的输入框"（内凹底 + 放大镜 + `/`）。
   实际上它确实可以直接打字（聚焦即展开），所以不算骗人；但如果你希望它明确是"按钮"，需要把它再降一档（去掉内凹底，只留图标+文字）。

## 五、落地映射

- `g1-notes.md` / `g2-notes.md` 里有各自的 `NavPage.tsx` 状态机改法、`styles.css` / `glass.css` 规则片段与取舍说明。
- 需要新增的状态：`searchOpen`（布尔）、`query`（已有）；焦点归还用 `triggerRef.current?.focus()`。
- `prefers-reduced-motion` 已由全局媒体查询覆盖；液滴形变需确认走 `--dur-base` + `--ease-spring` 而非手写曲线。
- 暗场落地时三级墨必须按 g2 的实测值重新校对，不能直接反色。
